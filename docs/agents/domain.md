# Domain Docs

This repo uses a single-context documentation layout.

## Primary docs

- `docs/resumo.md`: product vision, positioning, audience, market, metrics, and risks
- `docs/requisitos.md`: MVP functional requirements, non-functional requirements, business rules, and out-of-scope items
- `docs/prototipacao-frontend.md`: frontend UX, screens, flows, responsiveness, accessibility, and interface tone
- `docs/design_sistem.md`: visual foundations, tokens, reusable components, states, motion, and microcopy

## ADRs

Architectural decisions should live in `docs/adr/` when they are created.

Before changing code, read any ADRs that touch the area being modified. If no ADR exists, proceed silently.

## Vocabulary

Use the product language from the primary docs:

- "timing comercial"
- "empresas recem-abertas"
- "fase de timing"
- "Timing Score"
- "melhor janela"
- "watchlist"
- "alertas"
- "abordagem contextual"
- "Timing Intelligence"
- "Outreach Relevance"
- "Contextual Outreach"
- "Watched Business"

Avoid repositioning Kairos as a generic lead database, CRM, or mass outreach tool.
